## Quality check and the setting used from here (second pod, RTX 4090 24 GB, 43 GB RAM)

The first sets look coarse (faces, crowd and net smeared). One tennis run (source, depth, seed 43, frame 60;
`runs/tennis/generated/quality_check.png`): 40 steps instead of 20 helps a little; the 8-bit text encoder
instead of nvfp4 hardly changes anything; **control strength 0.7 instead of 1.0 gives a clearly sharper, natural
picture** (crowd, net, cloth), at the price of drifting from the control (arm position, umpire and chair placed
differently). Strength 1 holds the generator to the proxy depth too tightly. Setting chosen by the user's request
for one good setting: 40 steps, `qwen3vl_32b_minimax_h3_int8_convrot`, strength 0.7. Phase 1a and tennis are
regenerated with it into `runs/phase1a/generated_v2`, `runs/tennis/generated_v2`; whether the edits still
show there is checked on phase 1a. Time per run: tennis 286 s at 0.7.

## Decision: the ComfyUI r2v template, no ControlNet (2026-11-16)

Diagnosis on tennis source, seed 43 (`runs/tennis/diag/`): with the control switched off (strength 0) both ref2va
and fl2va give sharp, normal H3 pictures at 800x704 with the int8 weights, so resolution, quantisation and the
text encoder are not the cause. The coarse look comes from the Fun ControlNet holding the picture to the proxy
depth. Depth at 0.4 + reference image: sharp but the camera and the action leave the scene. Pose 1.0 + reference
image: sharp, the serve motion kept, the look not (white shirt, other venue).
**r2v** (`MiniMaxH3ReferenceToVideo`, as the ComfyUI r2v template, no ControlNet): `<Video 1>` = the scene's render
(camera, layout, motion), `<Picture 1>` = a full-size source frame with `ref_image_size: max`, a prompt that gives
each reference one job, 20 steps, `beta` scheduler, int8 text encoder. Result (`runs/tennis/diag/r2v_look.png`):
the player's look (blue shirt, black shorts, wristband), the blue seats and sponsor wall, the camera, layout and
serve motion all follow; picture quality close to plain H3. Crowd and board text differ from the source. A
search found nothing more reliable; a community fl2va/ref2va hybrid (21 GB, own loader) is a later option.
16-bit weights: not needed for this (they need an 80 GB GPU and a new 60 GB-class download).

Settings now live in profiles: `gpu/h3_control/comfy/profiles/*.json` (`r2v_tennis`, `r2v_synthetic`,
`control_depth_legacy`), `comfy_jobs.py --profile ...`. To adapt to a new problem, copy a profile and change one
key; meta.json records the profile and the exact prompt sent. Regeneration with r2v: `runs/tennis/generated_r2v`,
`runs/phase1a/generated_r2v`.

## Upload bug, the reference comparison, stage 2 (RTX 5090 32 GB, 56 GB RAM)

**Bug (fixed 12:00):** `Server.upload` reused the variable `name` in its form-field loop, so every upload was named
`overwrite` and replaced the previous one. Runs with one upload each (all Fun ControlNet runs, sequential) are
valid; every r2v run with a reference image before the fix had its image replaced by its video, so the "look"
came from the prompt alone. Those runs are in `runs/invalid_upload_bug/` and are not used. The pod stop at
12:07 was caused by a command given to the user (`pkill` on the timer's `sleep`, which let the timer go on to
stop the pod), not by RunPod.

**Reference comparison** (`evaluation/tennis/jobs_refs.json`, profile `r2v_refs`, `runs/tennis/refs_test/`,
`compare_ABC.mp4`), seed 43, source camera and orbit90: A depth video + one source frame; B clay video + source
frame + 4 crops (player full, upper body, serving, stands); C clay + depth videos + the same images. With the
references really used, all three come very close to the source on the source camera (player, US Open seats,
sponsor boards, bench) and follow the camera on orbit90. Differences are small; B keeps the player most stable.
Time per run on the 5090: A 6-8 min, B 6.7 min, C 13.6 min. **Chosen by the user: B.**

**Stage 2** (one seed): phase 1a with r2v (`runs/phase1a/generated_r2v`, `phase1a_r2v.mp4`, 13.6 min per run at
1280x704): all three edits show (camera view, tall block, start held to past frame 36); edge F1 .30-.54 against
.08-.26 with the ControlNet; unchanged objects MAD 5.4 / 4.6 (PSNR 28.5 / 26.6). Tennis B
(`stage2_tennis.mp4`): dolly follows the move; on orbit90 the full / soft / drop clay variants give nearly the
same video: with r2v the hypothesis treatment of the reference video hardly matters (D5 is not decided by this;
masks would be needed to measure small differences).
