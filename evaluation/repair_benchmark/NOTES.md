# 修理ベンチマークのメモ

`results.md` の読み方と、分かったこと。条件：領域は正解マスクの代用、誤差はわざと入れたもの、AIなし（決まった順番の仮説）。
だから、これは修理の仕組みの確認であって、研究の結果ではない（計画書 11.8）。

## 分かったこと

1. **画角を床・壁だけで判断させると、効くクリップと効かないクリップに分かれる。**
   - 効いた：syn_01 15.7% → 0.1%、syn_04 13.0% → 0.3%、syn_05 17.4% → 0.5%
   - 効かなかった：syn_02（10.9% のまま）、syn_03（15.9% のまま）、syn_06（14.9% のまま）
   - 物も含めて判断させた前の版では、syn_02 は 4.6%、syn_03 は 8.2% まで直っていた。そのかわり、syn_04 は悪化していた。
   - どちらのやり方にも弱点がある。物も含めると、物を動かして辻褄を合わせてしまう。床・壁だけだと、手がかりが足りないことがある。
2. **床と壁の輪郭だけでは画角が決まらない場面がある。** カメラがほぼ水平に前を見ていて、床と壁の境目が
   画面の中央付近にあると、ズームしてもその線がほとんど動かない（syn_02、syn_03、syn_06 はこれに近い向き。原因の推定で、未確認）。
   点の追跡や、床の模様などの手がかりが要る。
3. **タイミングは2フレーム前後が残る。** 一定の速さで動く物だと、「遅く動き出す」と「進む方向に少しずらして置く」が、
   画面上ではほぼ同じに見える。区別できる手がかりは、動き出しと止まる瞬間だけ。これは仕組みの問題ではなく、
   問題そのものの曖昧さ。
4. 箱の描き方を、面ごとに奥行きを比べる方式（Zバッファ）に変えて、正解どうしの損失が 0.10 → 0.03 に下がった
   （640×352）。損失の計算は半分の解像度で行う（約4倍速い）。

## 次に効きそうなこと（未検証）

- 点の追跡を観測に加える（2、3の曖昧さを減らせる可能性）
- 動き出しと止まりの区間に重みを置いたタイミングの損失
