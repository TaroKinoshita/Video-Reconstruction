# PLAN v2（2026-11-19）：LLM が作ったシーンを、編集できて V2V に使える形に整える仕組み

## 0. 目的（ユーザーの決定）

**目で見て、素の LLM より明らかに良い**動画を出す。数値での厳密な勝ち負けの証明は要らない。
比べ方：同じ実写動画から「素の LLM（Claude + Blender 直接操作）」と「この仕組み」でシーンを作り、
同じカメラの動き（回り込み 90/180 度、引き、クレーン）で V2V にかけて横に並べる。

## 1. v1.0 で分かったこと（設計の前提）

- 素の LLM の強み：元のカメラからの見た目合わせ（合成動画で IoU .78、4RC 始まりより上）、物の種類と配置の判断。
- 素の LLM の弱み（予想、まず実測する）：カメラの外が空っぽ、人が箱や棒人間、縮尺がでたらめ、
  動きがキーフレームでない（編集不可 23%）、カメラが他の物に拘束される、回り込むと崩れる。
- この仕組みの強み（テニスで実証済み）：コート較正（メートル単位）、人の体（GVHMR + SMPL-X）、
  会場のレイアウト（LLM + GPT Image でカメラの外を想像）、補完、状態管理、V2V 用の書き出し。
- 弱み：テニス用に手で組んだ部分が多く、他の動画にそのまま使えない。RQ1 では「箱の手直し」しか比べていない。
- 結論：**素の LLM の目と判断はそのまま使い、弱い所（幾何・カメラの外・人・動き・形式）を仕組みが受け持つ**。

## 2. 新しい設計：役割分担

```
動画 ─ 観測 ─────────────┐   SAM マスク、4RC（カメラ・点群）、GVHMR（人）、床の平面
                         ▼
  [A] LLM が「何があるか」を決める（構造化ツール経由。Blender コードは書かせない）
      物の一覧・種類・おおよその位置・動き・会場の種類 → vrecon Project（id・キー・状態つき）
                         ▼
  [B] 幾何の固定（仕組み）  カメラ＝観測から、床＝平面、物＝マスク＋奥行きに吸着、人＝GVHMR の体、
                           縮尺＝既知の大きさ（コート、ドア、人の身長）からメートルに
                         ▼
  [C] カメラの外の補完     会場レイアウト（LLM）＋外側の絵（GPT Image）＋規則（囲う・延ばす）＋形の部品庫
                         ▼
  [D] 回り込みの自己点検   要求されたカメラの動きで描き、穴・宙に浮いた物・欠けた人を自動で検出
                           → 足りない所を [A]/[C] に戻す（回数上限つき）
                         ▼
  [E] V2V 書き出し・生成   粘土映像＋元動画の切り抜き＋シーンから作った文章（実装済み）
```

一般化の原則（ユーザーの方針）：クリップごとの値は書かない。テニス用に手で決めた所（コート型紙、
スタンドの段差など）は「既知の物の部品庫」と「LLM が選ぶ会場の型」に置き換える。

## 3. 作業の段階

| 段階 | 中身 | 終わりの条件 | 目安 |
|---|---|---|---|
| P0 基準を作る | テニス＋実写2本で素の Claude を回す（1〜2回ずつ）。両方を同じ回り込みで粘土描画して並べる | 素の LLM の崩れ方を画像で確認し、[A]〜[D] のどれが一番効くか決める | 半日、Claude 約 $15 |
| P1 [A] 構造化ツール | MCP に「物を足す・種類を決める・動きを付ける・会場を選ぶ」ツール。出力は Project | 素の Claude と同じ動画で、同じくらい元の見た目に合う | 2〜3日 |
| P2 [B] 幾何の固定 | 既存の部品（4RC 変換、床、GVHMR 配置、較正）を汎用の関数に。縮尺は既知の大きさ表から | 実写3本でメートル単位・人が体で立つ | 2日 |
| P3 [C] 補完の汎用化 | テニス専用の会場作りを「会場の型（屋外コート、室内、道路、部屋）」に。GPT Image の外側の絵を全クリップで | 回り込み 90 度で穴の割合が素の LLM の半分以下 | 2〜3日 |
| P4 [D] 自己点検 | 回り込み描画で穴・浮き・欠けを測る関数（既存の coverage を拡張）、戻しの回数上限 | 自動で直る例が出る | 1〜2日 |
| P5 見せる | テニス＋実写2〜3本で、素の LLM とこの仕組みを同じカメラの動きで V2V。横並びの動画と静止画 | 目で見て明らかに違う。違わなければ原因を書いて P1〜P4 に戻る | 1日＋GPU 数時間 |

順番：P0 で弱点を実測してから P1〜P4 の優先順位を決める（全部を同じ重さで作らない）。
測るもの（補助、目視が主）：回り込みでの穴の割合、人が体として写っているか、元の見た目の一致、編集が通るか。

## 4. やらないこと

- 合成のおもちゃ動画での細かい数値比較（v1.0 で済んだ）。
- 素の LLM に勝つための個別調整（クリップごとの値）。
- 動画生成モデル側の改造。

## 5. 決めてもらうこと

- P0 で素の Claude を回す費用（約 $15）と、P5 の GPU レンタル。
- 実写の比較対象：テニス以外に 2〜3 本（手持ちのストック 12 本から選ぶ）。
