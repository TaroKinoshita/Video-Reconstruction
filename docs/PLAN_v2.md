# PLAN v2（2026-11-19、外部レビューを反映。7章が P1 の結果を受けた最終計画 2026-11-20）：LLM の初稿を保ったまま、崩れる所を観測で直す

## 0. 目的（ユーザーの決定）

**目で見て、素の LLM より明らかに良い**動画を出す。厳密な数値の勝ち負けは要らない。
狙う改善：**元のカメラで既に合っている見た目は保ち、横や引きから見ても手と物が離れず、
カメラの外が破綻せず、動きのタイミングを編集できること**。

## 1. v1.0 の読み方（前提）

- v1.0 で素の LLM に負けたのは「元のカメラから見た物体の重なり」だけ。最終的な V2V 映像での優劣は未決着。
  比べたのは合成のおもちゃ動画で、この仕組みの強み（カメラの外の補完、人の体、会場、状態管理）は入っていない。
- 元のカメラでは LLM が強い（本番6本すべてで Claude の初稿が 4RC＋手直しより上）。今の手直しは 4RC の誤差には効くが、
  LLM の残す誤差には効き方が違う（Claude＋手直し：改善1・悪化1・差なし4）。
- 編集が通ることには価値がある（4RC＋手直しは全12本で3種の編集が通る）。ただし編集後の絵は、どの方式も元の
  カメラほど合わない（未使用クリップでカメラ移動後の一致度：4RC＋手直し .515、素の Claude .533、Claude＋手直し .543）。
  ここが全方式に共通の改善点。
- テニスの完成例は土台として残す（引き・横の構図でも同じサーブを再現、人物の重心のずれは画面対角の約1%）。
  次に確かめるのは、ラケットと球の接触、背景との位置関係、別の素材でも品質が続くか。
- 画像生成（GPT Image）でカメラの外を描く効果は、テニスの観客席 IoU で なし .70／あり .68。全クリップ必須の根拠は弱い。

## 2. 設計

### 2.1 LLM の初稿 .blend を保持し、Project はその中を指す

- LLM（Claude + Blender）は制約なしで初稿を作る：メッシュ、親子関係、拘束、キーフレーム、何でも使ってよい。
  構造化ツールだけに制限しない（初稿の良いモデリングと動きを捨てないため）。
- システムは .blend のオブジェクトに id を振り、Project はその id と「編集できる取っ手」を持つ：
  カメラがリグの子ならリグ、物がパスに沿うならパス、焼き込まれた動きはキーに戻す、など。
  変更はこの取っ手経由で .blend に書き戻す（今の `blend_export` を拡張）。
- 先例：SceneCraft（シーングラフ＋Blender コード）、Thinking in Blender（静止画で段階的な Blender プログラム生成が
  忠実度を上げた）。動画での効果はこのプロジェクトで確かめる。

### 2.2 直す単位は「どの関係が、いつ崩れたか」

物体全体の位置・大きさではなく、関係と時間区間で直す。

| 崩れ方 | 見る観測 | 直し方 |
|---|---|---|
| 手と持った物が離れる | 手と物が同時に見える区間のマスク・追跡点 | その区間で相対位置を合わせ、物を手の子にする |
| 球が消える・跳ぶ | 見えるフレームの中心、ブラーの向きと長さ、消える前後の軌道 | 軌道を放物線などで埋める |
| カメラを横に動かすと物が滑る | 背景と前景の視差（LK 追跡点） | 先にカメラ（または奥行き）を直す |
| 動きの一部がカメラに逃げている | 背景の追跡点の静止 | カメラの動きを背景だけから決め直す |

LLM は「原因と変更の候補」を出す。採否は観測（LK・マスク・連続フレーム比較）で決める。
元のカメラの全体 IoU では拾えない失敗に直接効かせる。4DCodeBench でも、静止形状が作れるモデルが複雑な動きまで
正しく復元できるとは限らなかった。

### 2.3 カメラの外は「隠した実写」で答え合わせ

- 横を向く（パンする）実写を選び、前半だけを渡して空間を補完させる。後半で初めて見える壁・通路・家具が
  どこまでつながったかで確かめる。
- 完全な背面は、作品としてもっともらしいかを目で見る。
- 「穴の割合」だけを条件にしない（壁を一枚置くだけで達成できる）。通路が塞がれていないか、前景が隠れていないかも見る。
- 画像生成は、答え合わせで効くと分かったクリップの種類にだけ使う。

## 3. 比べ方

- **同じ LLM 初稿を2つに複製する。** 片方はそのまま、もう片方には観測から決めた修正を一つだけ入れる。
  初稿の当たり外れ（LLM のばらつき）を消せる。
- まず元のカメラ・横・引きの粘土描画を同じカメラで並べる。差が出たものだけ、同じ参照画像・プロンプト・シードで V2V に通す。
- 素材：テニス、**手に物を持つ実写**、**意図的なイージングのあるモーショングラフィックス**を各1本。
  接触・物理的な動き・演出された動きに同じ設計が通じるかを見る。

## 5. やらないこと

- 合成のおもちゃ動画での細かい数値比較（v1.0 で済んだ）。
- クリップごとの個別調整。
- LLM の作り方を最初から構造化ツールに限定すること。

## 6. 決めてもらうこと

- P1 の素材2本（手に物を持つ実写、モーショングラフィックス）：手持ちのストックから選ぶか、新しく用意するか。
- P1 で Claude を回す費用（3本×2回で約 $15〜25）、P5 の GPU レンタル。

## 7. 最終計画（2026-11-20、P1 の結果から）

### 7.1 P1 で分かったこと（`docs/P1_FINDINGS.md`、粘土の比較 `runs/p1/clay_*.png`）

- 素の Claude の初稿は、6本すべて「元のカメラが見ていない所」で崩れる：回り込むと会場や部屋が途切れて空になる、
  画面の端で切れた物が見えた分だけの塊として宙に浮く。
- 人の作りは回によってばらつく（アヒル r1 は脚だけ、r2 は手で紐を持つ子どもまで）。テニスの選手は関節付きのマネキン。
- 単純なモーショングラフィックスは素の LLM で崩れない。見せる素材には使わず、「悪くしない」確認にだけ使う。

### 7.2 作るもの（優先順）

すべて LLM の初稿 .blend に「足す・付け替える」形で入れ、初稿の物は消さない（取っ手経由で書き戻す、2.1）。

| 順 | 部品 | 中身（汎用、クリップごとの値なし） | 終わりの条件（目視） |
|---|---|---|---|
| 1 | カメラの外の補完 | 要求されたカメラの動きで描き、床・壁・会場の「途切れ」を検出 → 床と壁を見えなくなるまで延ばす（`run/complete.extend_set_to_view` を .blend 用に）、囲いの面を足す、会場の型（スタンド・部屋の家具並び）を LLM に選ばせて配置。元のカメラで見えている所は守る（`protect_depth`） | テニス・アヒルの回り込み45度と引きで、空の部分がなくなる |
| 2 | 画面の端の物を完成させる | マスクが画面の端に触れる物を検出 → 形の部品庫（`analysis/shape_library`）か、LLM に「全体の形」を作らせ、見えている部分のマスクと合うものだけ採用 | 引きで浮いた塊がなくなる |
| 3 | 人の付け替え | 人が映る所で GVHMR の体（SMPL-X）に置き換え、LLM の人形は外す。持ち物（ラケット、紐）は手の子にする | テニスで選手が体になり、ラケットが手から離れない |
| 4 | 関係の修正 | 2.2 の表：手と物、紐、球の軌道。LLM が候補、観測（マスク・追跡点）が採否 | アヒルで紐が手と玩具をつなぎ続ける |
| 5 | V2V で見せる | テニス・アヒル：同じ初稿の複製（そのまま／1〜4を適用）を、同じ参照画像・プロンプト・シードで V2V（回り込み45度、引き）。横並びの動画 | 目で見て明らかに違う |

### 7.3 進め方と時間（目安）

1. 部品1（2〜3日）→ 粘土で確認 → 部品2（1〜2日）→ 粘土で確認。ここで一度、粘土の横並びを見せる。
2. 部品3・4（各1〜2日）。
3. 部品5：ポッドを借りて生成（数時間、GPU 代）。差が見えなければ、原因を書いて 1〜4 に戻る。
4. カメラの外の答え合わせ（2.3 の隠した実写）は、パンする素材が見つかった時点で部品1の確認に加える。

### 7.4 費用

- Claude：初稿は済み（6本）。部品1の会場の型と部品2の全体の形で LLM を使う分、1本あたり数ドル。
- GPU：部品5の V2V。テニス・アヒル × 2条件 × 2カメラ = 8本。
