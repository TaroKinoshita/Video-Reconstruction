# 取り決め（CONVENTIONS）

- 版：v0.1（2026-10-31）
- 対象：`vrecon` のすべてのコード、保存データ、モジュール間のやり取り（PLAN.md 5.4）。
- ルール：外部ツール（解析OSS、Blender）の流儀は、**接続部分（アダプター）で必ずこの取り決めに変換**してから保存する。保存データの中に、別の流儀を混ぜない。

一目で分かる表：

| 項目 | 取り決め |
|---|---|
| ワールド座標 | 右手系、**Z軸が上**、単位はメートル |
| カメラの軸（保存データ） | **OpenCV式**：x右、y下、z前 |
| カメラの姿勢 | camera-to-world（カメラ → ワールド） |
| 回転 | 単位クォータニオン `(w, x, y, z)` |
| 行列 | 4×4、行ごとのリスト、列ベクトル式（`p_world = M @ p_cam`） |
| 角度 | 内部はラジアン。度は表示とレポートだけ |
| 画素座標 | 原点は左上、x右、y下。**画素の中心が整数**（OpenCV式） |
| カメラ内部パラメータ | `fx, fy, cx, cy`（画素単位）、`width, height` |
| フレーム番号 | **0始まり** |
| フレームレート | 分数で持つ（例：`24000/1001`） |
| ID | 文字列、種類の接頭辞つき（`obj_`、`cam_`、`shot_`、`evt_`） |

---

## 1. ワールド座標

- 右手系、**+Z が上**。Blenderと同じなので、ワールド座標はBlenderにそのまま渡せる。
- 単位はメートル。
- 床が分かっている場合は、床を `z = 0` にする。
- **大きさ（スケール）は映像だけでは決まらないことが多い。** だから、スケールの出どころを必ず記録する。

  ```json
  "scale": {"source": "assumed", "note": "机の高さを0.72mと仮定"}
  ```
  `source` は `assumed`（仮定）、`estimated`（解析ツールの推定）、`human`（人が指定）のどれか。

- 重力の向き（どっちが下か）も、推定の場合は記録する。解析ツールの出力は、ワールドのy軸が下向きなど流儀がバラバラなので、アダプターでZ上向きに直す。

## 2. カメラ

### 2.1 軸の向き

保存データでは、カメラの軸を **OpenCV式** で持つ。

```
OpenCV式（保存データ）        Blender式（ビルダーの中だけ）
  x：右                         x：右
  y：下                         y：上
  z：前（カメラが見る方向）       -z：前
```

OpenCV式にする理由：解析ツールの多くがこの流儀で出力するのと、再投影誤差の計算がそのまま書けるため。

### 2.2 姿勢

- camera-to-world の4×4行列。保存は `translation (x, y, z)` と `rotation (w, x, y, z)` で持つ。
- Blenderに渡すときの変換（ビルダーの中だけで行う）：

  ```
  M_blender = M_opencv @ diag(1, -1, -1, 1)
  ```
  （カメラのy軸とz軸を反転する）

### 2.3 内部パラメータ（画角など）

保存データは画素単位で持つ。

```json
"intrinsics": {"width": 1920, "height": 1080, "fx": 1500.0, "fy": 1500.0, "cx": 959.5, "cy": 539.5,
               "distortion": null}
```

- 画素の中心は整数。画像の中心は `((width-1)/2, (height-1)/2)`。
- レンズの歪みは、初期は無しと仮定する（`distortion: null`）。扱うときはOpenCVの係数の並びにする。
- 最初は正方画素（`fx = fy`、相対差0.1%以内）だけを扱う。違う場合、ビルダーは間違ったカメラを作らずにエラーにする（`pixel_aspect` での対応は、テストで向きを確かめてから追加する）。
- ズームしているカットでは、内部パラメータをフレームごとに持つ。

**Blenderへの変換**（センサーの合わせ方は `AUTO`、`S = max(width, height)`）：

```
lens_mm  = fx * sensor_width_mm / S
shift_x  = ((width  - 1) / 2 - cx) / S
shift_y  = (cy - (height - 1) / 2) / S
```

`sensor_width_mm` は36を標準にする。値に意味はなく、`lens_mm` との比だけが効く。
この変換式と2.2の軸の変換は、Blender 5.2.3 の投影（`world_to_camera_view`）と比べる自動テストがある（`tests/test_builder.py`。横長・縦長・主点のずれ・ズームを含む。許容誤差0.01画素）。

## 3. 回転

- 単位クォータニオン `(w, x, y, z)`、Hamilton式、能動回転（物を回す向き）。並びはBlenderと同じ。
- オイラー角は保存しない（軸の順番の取り違えと、ジンバルロックを避けるため）。表示用に出すときは、軸の順番を書く。
- アニメーションでは、隣り合うキーのクォータニオンの符号をそろえる（`q` と `-q` は同じ回転だが、補間が逆回りになるため）。Blender側の回転モードは `QUATERNION` にする。

## 4. 行列

- 4×4、行ごとのリスト（`[[r00, r01, r02, tx], ...]`）。
- 列ベクトル式：`p_world = M @ p_local`。
- 回転部分は正規直交であること。読み込み時に確かめて、外れていたら警告する。

## 5. 時間

### 5.1 フレーム番号とフレームレート

- フレーム番号は **0始まり**の整数。
- フレームレートは分数で持つ（`{"num": 24000, "den": 1001}`）。秒は `frame * den / num`。
- 可変フレームレートの映像は、取り込み時に固定フレームレートへ変換して、元の情報を記録する。

### 5.2 4種類の時刻（PLAN.md 5.3）

| 名前 | 意味 | 型 |
|---|---|---|
| `source_frame` | 入力映像の何フレーム目か | 整数、0始まり |
| `shot_frame` | そのカットの何フレーム目か（`source_frame - shot.start`） | 整数、0始まり |
| `scene_time` | 再構成した出来事の時刻 | 秒（小数） |
| `edit_frame` | 編集後のタイムライン上の位置 | 整数、0始まり |

- カットの範囲は `[start, end)`（終わりのフレームは含まない）。
- 単一カットの段階では、`scene_time = shot_frame * den / num` とする。

### 5.3 Blenderのフレームとの対応

Blenderのフレームは1から始めるのが標準なので、ビルダーの中だけで変換する。

```
blender_frame = shot_frame + 1
```

`frame_offset = 1` として、`.blend` 側にも記録する。

## 6. 画像と外部ファイル

| 中身 | 形式 |
|---|---|
| フレーム画像 | PNG、sRGB、8bit |
| 奥行き | float32、メートル（スケールが仮定なら仮定の単位）。`.npy` または `.exr` |
| 物体の領域 | PNG、uint16、画素値＝物体の番号、0＝背景。番号とIDの対応表を別に持つ |
| 点の追跡 | `.npz`（フレーム、点の番号、x、y、見えているか） |

- 外部ファイルは、ID・パス（プロジェクトからの相対パス）・SHA-256ハッシュで参照する。
- どのツールで作ったか（出所）を、ファイルごとに記録する（PLAN.md 10章）。

## 7. ID

- 文字列。種類の接頭辞＋短い名前か連番：`obj_chair_01`、`cam_shot003`、`shot_003`、`evt_sit_01`。
- 一度付けたIDは変えない。消した物のIDも再利用しない。
- Blender上では、物とカメラのカスタムプロパティ `vrecon_id` に入れる（読み戻しはこのIDで対応を取る。PLAN.md 7.2.1）。Blender上の名前は表示用で、対応付けには使わない。

## 8. 変更するとき

- この文書を変えたら、版を上げて、変更点を末尾に書く。
- 保存データの意味が変わる変更なら、`schema_version` も上げて、変換スクリプトを用意する（PLAN.md 10章）。
