# 会場の全周3D化 計画（2026-11-13）

## 目的
カメラを引いても、横・後ろを向いても成り立つ「完成した3Dの会場」を作る（テニスならテニス会場）。
見えていない部分は「映像と矛盾しない仮説」として作り、仮説であることを記録する。

## 決まった考え方
- 板を足すのをやめ、会場の構造を持たせる（例：コート外周に沿う段の観客席ブロック）。板は表面として使ってよい。
- 規格で決まる部分（コート 23.77×10.97 m、シングルス幅 8.23 m、ネット中央 0.914 m）と、会場ごとの仮説（観客席の囲み方・段数・屋根・通路）を分ける。
- 外側の想像は切り替え式：`none`（画像生成なし）／`fal`（画像生成あり）／`fake`（接続と保存の確認専用。品質比較には入れない）。
  `none` は「画像生成なし」であって「外部送信なし」ではない（LLMに元フレームを送る）。
- `none` と `fal` は同じ「会場構成データ」の形式・同じ部品・同じ調整処理につなぐ。生成画像から自由に作り直さない。
- 画像生成は同じ視点の画面外を含む会場案にだけ使う。元の部分は生成後に合成し直し、配置した位置・倍率も保存する。別の視点は3Dから描いて確認する。360°パノラマは参考扱い（視差や裏側は決まらない）。
- アプリ画面は作らない。コマンドで動かす。

## 評価（8）
- 元視点：物の欠落・余計な遮蔽（隠した画素の割合）・輪郭・コート線・動きの維持。隠した画素の割合だけにしない（物を消す・遠ざけると良く見えてしまう）。
- 新視点：浮き・交差・欠け、観客席や通路などの構成の自然さ（人の目、または画像を読めるLLMに決まった質問で採点）。
- 合成シーン：使っていない別カメラの映像・深度で確認。
- 後ろ側は答えが複数ありうるので、「正解との一致」と「会場としての妥当さ」は別に採点する。
- 総費用（画像生成費を含む）と実行時間を記録する。`fal` は複数回試す。

## フェーズEの画面外の絵（仕様）
- 同じカメラ位置・向き・透視投影のまま、キャンバスを2〜3倍に広げる（元画像が全体の半分〜3分の1）。倍率と元画像の位置を記録する。
- 描き方は2通りを試して、LLMが構成を読みやすい方を選ぶ：自然な見た目のまま／構成を強調して面の色分けをはっきり。
- 観客の顔・広告の文字・細かな質感は増やさない。根拠のない屋根やコートの追加、魚眼・パノラマ・鳥瞰への変更はしない。
- 見えない構造（手前の観客席の裏など）は1枚に描かせない。LLMが仮説として補う。
- 候補は3〜4案。選ぶ基準：元の部分が変わっていないか（マスク内の差）、コート・ネット・人の位置関係、構成の読み取りやすさ。LLMが選び、理由を記録する。混ぜない。
- 生成後、マスク内を元画像で必ず置き換える（マスクは誘導で、守られる保証はない）。境目のつながりを確認する。
- LLMへは4点を渡す：元フレーム／画面外を描いた絵／元の範囲を示すマスク／コート寸法・カメラ・既知の物の情報（プログラムで正確に作る）。
- 上面図・鳥瞰図は生成しない。採用した構成から3Dを作り、Blenderで描く。
- プロンプトの文面は試しながら直す。文面・モデル名・設定・結果を全部保存する。

## 別件：LLMに映像をどう見せるか（動きの再現）
現状：MCPの `run_look` は既定で映像全体から均等に4フレームを選び、横幅1280pxの1枚に並べて返す（`run/look.compare_sheet`）。フレーム番号は指定できるが、1枚に詰めるので増やすほど小さくなる。動きの細部（動き出し・停止・イージング・接触・出現）は落ちる。
方針：全部を一度に渡さず、全体把握 → 機械で候補区間 → 区間をコマ送りで精査 → 数値で確認 → 元映像と再構成を同じフレームで比較。道具として足すもの：
- 指定フレーム1枚（フレーム番号付き、原寸に近い大きさ）。
- 短い区間の連続フレーム（例：0.5秒を元のfpsのまま8〜16枚、番号付き）。
- 部分拡大（小さい物用）。
- 元映像と再構成の同じフレームの比較（重ね・差分）。
- 機械が拾った候補区間の一覧（フレーム差分・LKの軌跡からの動き出し・急変・遮蔽・追跡失敗）。
効果は、変更前後でタイミング誤差・動きの誤差・処理時間を比べて確かめる（以前の「見る係」が伸びなかったのは、見られるフレームと選べる修正が限られていたせいかもしれないが、未確認）。

## フェーズA：固定したもの（2026-11-13）
- 確認用カメラ：`evaluation/venue/cameras.json`（比較の前に決めた。方法をこれに合わせて調整しない）。
  - 合成 ven_01：source（南ベースライン後ろの低い位置。テニス映像に似せた）／pullback_high（引いて上から全体）／side（東スタンドからコート越し）／high（ほぼ真上）／back（振り返って南側：元のカメラが一度も向いていない側）。
  - テニス：source／pullback = dolly-100+crane4／side = orbit90／high = crane10／back = orbit180（`scripts/camera_moves.py`、動きの最後のフレームで見る）。
- 合成会場 ven_01：`scripts/make_venue_clips.py`。ITF寸法のコートとネット、北15段・南12段・西20段・東20段（ネットの線に6 mの入口）、各スタンド前に1 mの壁、審判台・ベンチ2、選手2。元のカメラに映るのは北スタンド・北の壁・コート・ネット・選手だけ（残り12個は見えない）。
  - 評価専用：gt.json、meta.json、gt_passes/（再構成もLLMも読まない）。
  - 入力に使ってよいもの：source.png（元の視点の絵）、observed.npz（元の視点の画素ごとの3D点＋物のラベル、奥行きに1%のノイズ。4RC＋SAMの代わり。再生成できるのでコミットしない）。
- 採点：`scripts/score_venue.py CANDIDATE.json`（`metrics/venue.py`）。物のidではなく種類（床・コート・ネット・観客席・壁・備品・人）で比べる。
  - 新しい視点：種類ごとのIoU、covered（正解がある画素を埋めた割合）、extra（正解が何もない所に描いた割合）、same_category、depth_rel（奥行きの相対誤差の中央値）。
  - 元の視点：observed_kept（見えていた種類の画素が同じ種類のまま残っている割合）。隠した画素の割合だけでは測らない。
  - 正解そのものを採点して全部1.0になることを確認済み。
- テニスには見えない側の正解がない：元の視点の守り方（`scripts/source_view_change.py`）と、妥当さの採点だけ。
- 妥当さの採点（後ろ側は答えが複数ありうるので、正解との一致とは別にする）：確認用カメラの絵を人か画像を読めるLLMに見せて、決まった質問に答えさせる：
  1. 浮いている物はあるか。2. 物同士が突き抜けているか。3. 途中で切れている・穴が空いている所はあるか。
  4. 観客席は段になっていて、コートの方を向いているか。5. 通路や入口があるか、会場として行き来できそうか。
  6. この場所がテニス会場に見えるか。7. 元の視点で見えていた物が変わっていないか。
  各問 はい／いいえ／分からない、と一言の理由。

## フェーズB：コートの校正（2026-11-13）
- `analysis/court.py` + `scripts/calibrate_court.py`：白線（トップハット＋彩度、マスクした物は除く）→ 長い直線 → ITFコートへの当てはめ。線2本×2本の組み合わせを全部試し、コートの線が白い画素に乗る数（見えない所＝人・ネット・スタンドの陰は数えない）で選ぶ。180°の双子は手前側のカメラを採る。
  最初のフレームだけ全探索、以降は前のフレームの線の近くで追跡（312フレーム中157を2フレームおき、26秒）。手動モード（交点のクリック）も用意。
- テニス：手前ベースライン・サービスライン・左のシングルス／ダブルスのサイドラインで一致。カメラは動かず（位置を固定して当て直し）、ズームなし（焦点距離の傾き0.5%、ばらつき1.4%）→ 焦点距離2104 pxで固定、向きだけ毎フレーム（ゆっくり0.9°パン）。白線への乗り：中央値0.99、最小0.91。
  自由に当てると焦点距離と距離が入れ替わる（2065〜2209 px）ので、固定してから当てる。
- 確認：ネット上端の投影がSAMのネットの上端と中央値3 px差。メインの選手の身長がこの縮尺で1.84 m（本人1.85 m）。足元はベースライン上（Y = -11.9 m）。
- 4RC（焦点1872 px）とは画角が違う：似た形のまま移すだけでは、遠くの物や端の物が画素からずれる（遠くの人のIoU .67 → .04）。
  → `analysis/to_court.warp_model`：4RCの点は同じ画素・同じ距離（×メートル換算）のまま新しいカメラの光線に移す。`proxies_scene.py --calibration` でコートの座標（メートル、原点コート中央）で作り直す。床は4RCの床（0.74°ずれ）ではなくコート平面。単位は `units.json`（`analysis/units.py`）。
  結果 `runs/human/tennis/court_proxies/`：ネット高さ0.90 m、椅子0.47×0.47×0.89 m、人1.25〜1.71 m。IoUは移す前とほぼ同じ（人 .73/.81/.61/.50、ネット .75）。
- 4RC由来の位置のずれも見えた：ネットがY = +1.9 m（規格では0）。フェーズCでは規格で決まる物（ネット・コート）は規格の位置に置く。
