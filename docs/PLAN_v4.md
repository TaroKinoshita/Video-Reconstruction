# PLAN v4：1人1体・元映像に戻って直す（2026-11-23）

元：GPT のレビュー（docs/REVIEW_REQUEST_2026-11-23.md への回答）と追加の参考
（Human Mesh Recovery from Multiple Shots / HumanMM / Multi-THuMBS / SLAHMR）。
DESIGN_v3（証拠＋エージェント＋検証）は残す。変えるのは「証拠」の作り方：推定をそのまま固定せず、
元映像（2D の観測）に戻って、人の体・姿勢とカメラを直してから固定する。

## 原則
- 同じ俳優は、体型と骨の長さを全カットで共有する（1人1体、1つのリグ）。
- 姿勢・位置のつながりは、同じ動作が続いていると映像から言えるカットの間だけに使う（時間の省略・切り返しは切る）。
- カメラはカットごと。カット間で共有するのは、同じ場所と確認できた背景だけ。
- 良し悪しは元映像の上で測る：背景の画素のずれ、見えている関節の画素のずれ、同一人物の骨の長さ、手と物の位置。
- どの動画にも同じ仕組みで効くこと。クリップごとの手直しはしない。

## やめるもの
- アップの姿勢を1つ選んで全フレームにコピーする処理（`multishot_closeups.py` の `np.repeat`）。
- 3D 関節の点だけに SMPL を合わせる当てはめ（`fit_smpl.py`）→ 元映像の 2D に合わせる当てはめに置き換え。
- 「推定をそのまま固定の証拠にする」：直してから固定する。

## 追記（GPT の回答、2026-11-23）：食い違ったとき、どちらが間違いかを決める工程
join の後、SMPL・セットを作る前に置く（フェーズ1・2で作り、3で全カットへ）：
1. 推定器とは別経路の観測を保存：背景の静止点の 2D 軌跡、人物の見えている関節（ViTPose）と部位の輪郭、小物の輪郭・手との接点・前後関係。フレーム・可視性・信頼度つき。推定器の 3D を 2D に戻して同じ推定器を採点しない。
2. 変える対象を限った候補を比べる：現行／カメラだけ／人体だけ／両方（焦点距離・背景形状が怪しければそれも候補）。体型は人物ごとに共有、姿勢はフレームごと。
3. 合わせ込みに使わなかった点で採否：背景は軌跡ごとに調整用・検証用に分ける。人物も検証用の点（手首・顔）を残す。背景・人物・小物の誤差を別々に記録。検証点が悪化する案は捨てる。
4. 証拠が足りない区間は「未確定」として後段へ（アップのカメラ距離、画面外の脚など）。引きから得た体型は保つ。
- GPT の試験（cut 4 冒頭）：背景の対応点では、単独 4RC のほうが複数カット 4RC より元映像に合う（中央値 1.9 px 対 3.5 px）。後半は約21フレーム離すと対応点が足りず判定不能。縮尺はこの検査では決まらない。
- 参考：HSfM（人体・カメラ・背景を一緒に直す目的関数）、SLAHMR（時間方向）、Multi-THuMBS（編集点）。
- 最初の自動化目標：cut 4 で「どの区間で、どのカメラ案が、何本の背景軌跡に支持されたか」を返す。次に cut 2 の手首・顔で「静止姿勢」対「共有人体＋18フレーム」を測る。
